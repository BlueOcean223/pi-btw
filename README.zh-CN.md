# pi-btw

[English](README.md) | **简体中文**

给 [Pi](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) 加一个 `/btw`：就着当前这段对话问一句，拿一个回答，主任务照跑。

```text
/btw WBC 在这份 diff 里是什么
```

主 Agent 不停、不被 steer，也看不见这个问题。回答出现在输入框的位置上，不进主 transcript，也不写进会话文件。

## 为什么不直接问

Pi 里已经有三条路能问，每条都有代价：

| | 会发生什么 |
| --- | --- |
| 流式中直接回车 | steer 主任务，问题变成工作的一部分 |
| Alt+Enter | 排成 follow-up，等主任务跑完才答 |
| 另开一个会话 | 不知道「这份 diff」指的是哪份 |

`/btw` 是第四条：同一份上下文，另一个只答一次的 agent，什么都不写回去。

## 能做什么

- **用这段对话自己的上下文回答**——系统提示、工具 schema、主循环上次发出去的那批消息，所以「这份 diff」「那个函数」指的就是你以为的那个
- **沿用主请求的前缀**，逐字节一致，让旁问从 prompt cache 里读，而不是为同一份上下文再付一次写入
- **不会动手。** 工具一个都不执行。schema 留在请求里是为了缓存，也没有任何东西把工具结果喂回去。模型如果把工具调用写成正文，下面会多一句说明：那些都没有执行
- **每个会话最多记 20 条**，只在内存里。旧旁问之间互相看得见，主任务仍然看不见它们
- **空的 `/btw` 重开最近一次**，还在进行中的那次会直接接上

## 按键

| 键 | |
| --- | --- |
| `Esc` | 中止这次请求并关闭 |
| `Enter` / `Space` / `Ctrl+]` | 关掉。请求继续跑——空 `/btw` 能接回来 |
| `↑` / `↓` | 滚动回答 |
| `[` / `]`，或 `Shift+←` / `Shift+→` | 在最近几条旁问之间切换 |
| `c` | 复制回答的原始 markdown |
| `x` | 清掉面板上方那列历史，当前这条还在 |

只有 Esc 会中止。Claude Code 里「收起」和「关掉」是两条路径，只有一条会 abort；这里面板占着键盘，用户要看主界面只能先关掉它，所以关掉必须是免费的。

## 安装

```bash
pi package add @blueocean223/pi-btw
```

或者直接指向本地目录：

```bash
pi --extension ./index.ts
```

## 几点说明

- **只在交互界面可用。** `print`、`json`、`rpc` 模式下 `/btw` 会说明这件事，并且不发请求。
- **旁问看见的是主循环上次发出去的那份请求**，不是它的回复。这之后才落进会话的工具结果，要等主循环再发一次，下一句 `/btw` 才看得见。
- **面板开着的时候它占着键盘**，主任务的中断键按不到。先关面板。
- **问答列表活得和进程一样久。** 切到别的会话再切回来还在；退出或 `/reload` 之后就没了，空 `/btw` 又只剩用法提示。
- **不是每次主请求都能当前缀复用。** 在接受中途 system 消息的那几个 Claude 模型上，body 若以一条提示词分段更新结尾，
  就不复用它，这次旁问改走重建，缓存要等主循环下次发请求才重新命中。
- **`PI_BTW_DEBUG=1`** 会在每次回答之后打一行 `cacheRead`/`cacheWrite`。命中的第二次旁问应该大部分从缓存读、几乎不写；读是 0 而写接近整段上下文，说明前缀和主请求不一致了。

## 这一版明确不做

- **把一条问答提升成真正的分支。** Claude Code 的 `f` 把这一问一答塞进一条平行 fork，主会话继续跑。Pi 的 `ctx.fork` 会拆掉当前 runtime 并切过去，主任务就停了——那正是 `/btw` 要避免的事。
- **给旁问工具。** 那是另一个功能；这里的权限模型是 schema 为缓存而留，调用永不执行。
- **句子中间的 `/btw`。** Pi 只从整段输入的开头识别命令。
- **图片提问。** 问题只有文本。父前缀里已经有的图片跟着走。

## 开发

```bash
bun test ./*.test.ts   # 纯函数：复用改写、抽取分叉、cache_control 位置
bun x tsc --noEmit
```

`node_modules/@earendil-works/*` 符号链接到本机装的 Pi，所以类型检查针对的是你实际跑的那个版本。
